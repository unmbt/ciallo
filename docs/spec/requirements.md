# 项目定位、生态辨析与需求规格矩阵

## 1. 项目背景、核心定位与生态边界

### 1.1 生态痛点与项目定位

MoonBit 是一门原生编译至 **Native**、**WebAssembly** 与 **JavaScript** 的现代多后端语言，非常适合构建同时服务传统服务器与边缘 Serverless 节点的高性能 Web API。然而当前 MoonBit Web 生态存在显著的“底层割裂”与“工程代差”双重空白：

1. **后端部署与传输层锁死**：官方及部分社区后端框架重度绑定 `moonbitlang/async` / `core/async/http` 服务端（其 `Headers` 为与收发器强耦合的单值 `Map` + 独立 `Cookie` 数组），彻底放弃了 `js` 后端，无法编译并部署到 Cloudflare Workers、Vercel Edge、Deno Deploy 或 Node.js Serverless；而主打 JS 全栈的方案又缺乏一套独立于框架、可被整个社区复用的纯血 Web 标准协议包。
2. **现代工程能力分散**：大型 API 项目所需的**显式分阶段生命周期**、**默认局部作用域隔离与插件去重**、**全分支错误契约（含 400/401/413/415/422 等）**、**出参自动脱敏防泄露**、**OpenAPI 3.1 自动导出**以及**生命周期耗时 Trace 审计**，目前散落在不同仓库甚至尚属空白。

**`ciallo` Workspace** 采用 **`moon.work` 多模块工作区 + `unmbt/moonset` 发版治理**（详见 [ADR-005](../decisions/005-workspace-multi-module-and-moonset-release.md)、[ADR-011](../decisions/011-v1-rc1-alignment-and-contract-hardening.md) 与 [ADR-012](../decisions/012-int32-nullable-cancel-safety-and-v01-slimming.md)），核心定位是 **“底层做标准，上层做代差，节奏分步走”**：

1. **独立发版的 WinterTC / ECMA-429 Web 标准包 `unmbt/webstd`（四目标纯核）**：将 `Method`、`status_reason`、`Headers`、`Url`、一等公民结构化 `Cookie`（`max_age : Int64?`，防头注入）、`Body`、`ByteStream`、`Request`、`Response` 及 **SSE / NDJSON Streaming** 抽离为完全独立、零 I/O、零异步、全四目标（`native`、`js`、`wasm`、`wasm-gc`）的独立模块 `unmbt/webstd`，不仅支撑 ciallo，也可被任意 MoonBit 框架、客户端或前端 `wasm-gc` 包零负担单独引入。
2. **ElysiaJS 级工程深度 + Spring/GoFrame/Tower 精华降维吸收（`unmbt/ciallo`）**：全面对齐规范名 `Int32`/`UInt32`，用 MoonBit 原生 `enum`、`pub(all) suberror`/`raise`、`trait`、`#derive(ToJson, FromJson)` 落地 **9 阶段显式管线（路由匹配严格锁死在阶段 1–2 之间，首次 `fetch` 拍平冻结）**、**`Local`/`Scoped`/`Global` 作用域隔离与 `use_plugin` 深拷贝六项合并**、**统一受检 `AppBuildError`**、**原生 `raise` 强类型 Extractor（语法破损 `400` vs 契约违例统一 `422`）**、**手写 RFC 9457 `ProblemDetails`（顶层扩展扁平化 + `HttpError` `loc~`）**、**`NoContent`（`204`）哨兵**、**`Nullable[T]`（`PATCH` 三态）+ `Base64Bytes` + `SchemaRef` + `Int64String` + 双轨脱敏**、**OpenAPI 3.1（`ResponseKind`）+ 可离线 Scalar UI**、**有界队列取消安全 SSE 心跳**、**内置 `Trace` + W3C `traceparent`** 与 **`Lifecycle` / `CapabilityBundle` 标准装配协议**。
3. **统一 `dev_build` 代码生成与端到端 RPC 闭环（`unmbt/ciallo-gen`）**：彻底消灭 `SchemaNode` 与 `struct` 的双数据源分裂——仓库内外共享同名双模 `rule` + `dev_build`，在 `v0.1` 通过 `#ciallo.schema`（严格识别 `moon fmt`/`moon fix` 规范拼写 `Int32`/`UInt32`/`T?` 委托 `@schema.schema_ref_of`）自动生成 `Schema` 实现，并通过 **`ciallo-eden`** 配合 `sync_openapi` 消费 `openapi.json` 导出 **强类型 MoonBit SDK** 与 **零依赖 TypeScript SDK（`.ts` + `.d.ts`）**（编译期 DI `wire` 随多层数据组件在 `v0.2` 扩展）。
4. **独立平台适配器、外围按需微包与清晰三代演进**：同一份业务代码（`examples/shared-api`）可分别经 `unmbt/ciallo-native`（`idle_conns` 秒醒 + 子协程有界排空 + 早退未读 Body 断连 + UTF-8 `Content-Length` + 1:1 `Cookie` 桥接）与 `unmbt/ciallo-js`（`FixedArray` FFI + `#export_name("fetch")` + 2 行 `worker.mjs` 薄胶水空降 Cloudflare Workers）部署；按 **`v0.1`（Web 立威）→ `v0.2`（全栈数据闭环：PG + SQLite/D1 + `ciallo-migrate` + Redis + 事务回滚测试 + `wire` DI）→ `v0.3`（企业级 `ciallo-kit` + `ciallo-mcp` + WASI/WS）** 分步演进，并将 MongoDB 与 MySQL 方言置于独立孵化轨道。
5. **Serverless 一等公民上下文 + `moonset` 发版与包级 `SKILL.md`**：通过 `EnvBuilder` + 运行期纯只读 `Env`、`ExecutionContext::wait_until` 与可移植能力 trait（`KvStore`、`HttpClient`、`Clock`、`HealthCheck`）根除跨请求污染；整个 Workspace 由 `unmbt/moonset`（默认分支 `master`）自动规划版本、生成 Changelog 并按拓扑序发布，每个公开包自带面向 AI Agent 的 `SKILL.md`。

### 1.3 明确非目标（Non-Goals — 智能体严禁越界实现）

* **不做运行时 `eval` / 动态代码生成**：不模仿 ElysiaJS 的 `Sucrose` 动态拼接字符串 JIT/AOT 机制，性能由 MoonBit 静态编译、编译期 DTO 零开销轨道与零分配路径调度保障。
* **不做运行时反射 IoC 容器与弱类型动态大单体**：坚决不抄 Spring/NestJS 的运行时反射字符串 Token 容器（会毁掉 Tree-shaking、冷启动与编译期检查），也不抄 GoFrame 的大单体耦合与弱类型 `gvar.Var`；依赖反转由编译期 `ciallo-gen wire`、强类型能力容器与 MoonBit `Virtual Package` 完成，工具箱按独立可 Tree-shake 微包（`ciallo-kit`）拆分（详见 [ADR-008](../decisions/008-compile-time-di-lifecycle-bundles-and-enterprise-kit.md)）。
* **不引入外部 `moonbitlang/async` 并执行三级依赖治理（Tier 0/1/2）**：对齐 `unmbt/moonset` [ADR-003](../../../moonset/docs/decisions/003-core-async.md) 与本项目 [ADR-002](../decisions/002-core-async-and-multi-target-matrix.md) / [ADR-010](../decisions/010-phase0-precheck-resolutions.md) / [ADR-011](../decisions/011-v1-rc1-alignment-and-contract-hardening.md)：Tier 0（`unmbt/webstd`）生产代码仅限 `moonbitlang/core`（禁 `core/async`）；Tier 1（`unmbt/ciallo`、`ciallo-native`、`ciallo-js`、`ciallo-testing`）仅限 `moonbitlang/core*` 与工作区内 `unmbt/*`，**零第三方运行时依赖**；仅 Tier 2 构建期 CLI（`ciallo-gen` 允许引入官方 `moonbitlang/parser`）及 `v0.2`/`v0.3` 独立驱动桥接包/密码学微包可按 ADR 引入受控依赖，绝不反向污染 Tier 0/1。
* **不在核心 Web 层绑定具体数据库/ORM 驱动或企业级重型工具**：`unmbt/webstd` 与 `unmbt/ciallo` 绝不硬编码 SQLite、PostgreSQL、D1、Redis、MongoDB 驱动或重型中间件，核心仅通过 `runtime` 提供轻量可移植抽象（`KvStore`、`HttpClient`、`Clock`、`Lifecycle`、`HealthCheck`）；官方数据套件（`v0.2` 聚焦 PostgreSQL + SQLite/D1 + `ciallo-migrate` + Redis）与企业级 `ciallo-kit`（`v0.3`）均作为独立可插拔模块交付，绝不做“强行统一 SQL 与 NoSQL 的万能 ORM”（详见 [ADR-006](../decisions/006-data-suite-orm-redis-mongodb.md)、[ADR-009](../decisions/009-phased-release-cadence-v01-v03-and-incubation.md)）。
* **不做前端 UI / SSR 组件树框架**：不实现类似 `rabbita`、`luna` 或 `sol` 的虚拟 DOM / Island 渲染引擎（前端框架可自由挂载于 ciallo 之上并通过 `ciallo-eden` 消费强类型 RPC SDK）。
* **不在 `v0.1`/`v0.2` 强行铺开 WASI `wasi:http`、WebSocket、MongoDB SDAM 与 MySQL 方言**：严格遵循 [ADR-001](../decisions/001-neutral-http-core-and-runtime-adapters.md) 与 [ADR-009](../decisions/009-phased-release-cadence-v01-v03-and-incubation.md) 的收敛节奏：`unmbt/ciallo-wasi`、`WebSocket` 与 `ciallo-kit`/`ciallo-mcp` 排入 `v0.3`；`unmbt/ciallo-mongo` 与 MySQL 方言归入独立孵化轨道（`Deferred`），不阻塞主线发布。
